A bounded integer's `min`/`max` are now APPLIED by the element, not only written on it — and its refusal is the field's own.

**The bound.** The walker measured the deployed year field as `type="text" min="2017" max="2021" inputmode="numeric" pattern="[0-9]*"` (D439). The ends were the right ones — the chosen generation's, out of the catalogue — and a text input applies neither, so a number decades outside them left a field the browser called valid and only the server refused. `type="number"` is not the way back: it hands a phone a spinner nobody can hit and reports `value === ""` for anything it dislikes, deleting the half-typed number `SkinNumberField` exists to preserve, which is why that component refuses it. Native **constraint validation** is the half that does apply to a text input, so both int editors now hand the browser the same sentence the person reads: `checkValidity()` says false, `validity.customError` is set, `validationMessage` carries the words, `:invalid` paints, and a native submit stops. A custom validity is a STATE and not an attribute, so React remains the only owner of what is rendered — and nothing is clamped: the number typed is still the number in the box and still what `onChange` reports. The wrapper stamps `data-int-bound="refused" | "ok"` for a probe reading a snapshot rather than the API.

**The refusal.** The bounded int's out-of-bounds sentence was a `<HintLine>` standing next to the control, addressed by nothing. It is `SkinNumberField`'s `errorText` now — the same move the vocabulary-backed int made — so `aria-describedby` ties it to the input and the person who cannot see the line beside the field is told what the person who can is told. The box takes antd's error status with it. The test id (`attributes-int-out-of-range`) and every existing sentence are unchanged.

Measured with dependencies held constant, this package's src before and after: the `default` bundle 19.07 -> 19.20 KB, inside the standing 19.25 KB ceiling.

**And a gate for the chip that announced its storage code.** The walker found five chips across two categories whose accessible name was the slug while the screen showed a word (`levyy` for the steering side, then `sim-esim`, `ne-rabotaet-vspyshka`, `vosstanovlennyy`, `korobka` — every one of them the FIRST chip of its group, which is the signature of a build whose `@stapel/tokens-antd` predates `ChoiceChipOption.ariaLabel`). `chipOptions` states the resolved label on every chip, and the peer floor (`>=0.17.3`) makes the combination that leaks uninstallable; what was missing was the test that keeps it that way. `test/chipNames.test.tsx` holds a chip's accessible name against its label for the single `select`, the multiple one, the required `bool`'s tristate and the closed integer list — with labels that share no character with their codes, and once more inside a narrow column, where the label is a NODE and the name has nowhere to come from but the caller.

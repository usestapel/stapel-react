**A draft may exist without a category, and the composer now makes one that way.** The SAVE gate no longer requires a category (`firstBlock(mandate, busyGate)`); `ensureListingId` creates the row whether or not one has been chosen, and `createDraftBody()` sends `{}` when it has not — both valid since stapel-listings 0.21.4 made `category_id` nullable on the draft half. The composer could not create the row before the category step, so the analysis job addressed by the draft id had no id to start from and never started. `draftPatchFromValues` omits `category_id` while unchosen rather than sending `""`, and the category picked later is written by the next `save-draft` like any other field. Publishing is unchanged: the category is still on the publish gate, which refuses with "choose a category" ahead of the server's own `publish_validation_failed`. Both seeds read `category_id: null` without crashing — `ListingDetail`/`ListingDraft` now declare it `string | null`, a hand-written relaxation of a READ that an older backend still satisfies — and `bag.stage === "choosing_category"` no longer implies "no row yet"; `bag.listingId` is the answer to that.

**Digits are grouped only where they measure something.** A spec row printed a model year as `2 024`. `formatSpecValue` now groups when the feature carries a unit (`prefix`/`postfix`/`postfix1000`) or when the magnitude is at least 10 000 — a threshold no year, floor or room count reaches, so years are sorted from quantities without a "does this slug look like a year" heuristic that a non-English slug would defeat. `2024` stays `2024`, `4` doors stays `4`, `20 000 km` and `42 m²` are unchanged. Grouping is switched off through `Intl.NumberFormat`'s `useGrouping` rather than around it, so a unitless float keeps the reader's decimal mark.
